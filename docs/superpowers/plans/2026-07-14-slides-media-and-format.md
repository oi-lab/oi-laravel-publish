# Slides Media + Format Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the `slides` block a block-level display format and let each slide optionally link its own attachment, while fixing three coherence regressions in the recent Blocks + Enums changes.

**Architecture:** All work is in the `oi-lab/oi-laravel-publish` package (data layer only; no host copy exists). Rename the `CoverRatio` enum to a shared `MediaRatio`; add a `media_ratio` prop to `SlidesData` and an `attachment_uuid` reference to `SlideItemData`; remove the duplicated `navPosition` prop; and normalise recently-added style fields to snake_case. Attachment linkage is by the `Attachment.uuid` (auto-generated by `AttachmentObserver`), resolved by the host at render time. Validation stays on the typed `PropsData` attributes, not the generic request.

**Tech Stack:** PHP 8.4, Laravel 12, `spatie/laravel-data`, Pest v4, Laravel Pint.

## Global Constraints

- PHP 8.4; every method/function has an explicit return type; curly braces on all control structures; constructor property promotion.
- `Data` field naming is **snake_case** for multi-word fields (`cover_ratio`, `per_view`, `form_key`) — the whole point of two of these tasks.
- Props never carry content (title/lead/body are the block's columns). A reference id (`attachment_uuid`) is a link, not content, and is allowed.
- Style classes are **composed, never inherited** — `oi-laravel-ts` reflects only the constructor of the class it reads.
- Resolve models/templates through `OiLab\OiLaravelPublish\OiLaravelPublish`, never hardcode `::class`.
- Run `vendor/bin/pint` before each commit. Tests are Pest: run from the package dir with `vendor/bin/pest`.
- All commands run from `packages/oi-lab/oi-laravel-publish/` (referred to below as the package root). This is the git repo root for these commits.
- After behaviour changes, `composer sync-ai-skills` regenerates the AI context.
- Do **not** amend `.gitattributes` further — `/docs/superpowers export-ignore` is already added so specs/plans stay out of the Packagist dist.

namespace OiLab\OiLaravelPublish\Data\Blocks;

use OiLab\OiLaravelPublish\Data\CtaData;
use OiLab\OiLaravelPublish\Data\PropsData;
use OiLab\OiLaravelPublish\Data\Styles\SlidesStylesData;

use Spatie\LaravelData\Attributes\Validation\Min;

/**
 * Props for a "slides" (carousel) block. Slide images live in the block's
 * `slides` attachment collection; each `SlideItemData` links the one it shows by
 * `attachment_uuid`, so a slide can be text-only (no attachment) without shifting

        public bool $loop = true,
        public MediaRatio $media_ratio = MediaRatio::Inherit,
        #[DataCollectionOf(SlideItemData::class)]
        public array $items = [],
        #[DataCollectionOf(CtaData::class)]
        public array $ctas = [],
        public SlidesStylesData $styles = new SlidesStylesData,
    ) {}
}

use Spatie\LaravelData\Attributes\Validation\Max;
use Spatie\LaravelData\Attributes\Validation\Nullable;

## Notes on approach

- **Coherence fixes and features are interleaved by file, not batched**, so each commit is a self-contained, reviewable slice with its own test cycle.
- **No `PublishBlockRequest` change** (see spec §5): props validation lives on the typed `PropsData` attributes; the generic request keeps treating `props` opaquely and cannot check uuid referential integrity at create time anyway.
